# gitleaks' default rule file (vendored)

`gitleaks.toml` is gitleaks' own default configuration: its secret rules, their keywords, entropy thresholds and allowlists. It is vendored as the bundled offline rule set of [DEC-43](../../../../docs/design/DECISIONS.md) and [DEC-44](../../../../docs/design/DECISIONS.md), so a history or diff scan without gitleaks installed and one with it report the same rule ids. The gitleaks program is run with this same file as its harness-owned `--config` (not `useDefault`, which would mean the installed binary's own built-in rules), so both paths use one rule set whatever gitleaks version is installed.

- **Source:** the `config/gitleaks.toml` of gitleaks **v8.30.1**, <https://github.com/gitleaks/gitleaks> (the file says it is generated by gitleaks' `cmd/generate/config`).
- **Retrieved:** 2026-09-27, once, with the owner's approval.
- **`gitleaks.toml` SHA-256:** `e163e53b9e7e8a8511e77271e2b323ed057759542a6d988258afe3a1fa329caf` (222 `[[rules]]`).
- **`LICENSE` SHA-256:** `e3884b252b3bfc045e55be43a34d1e80da070bc6f804ac95bf4660e97d62ebc6` (gitleaks' MIT licence, as published with that release).
- **Kept:** the file byte for byte; nothing was changed.
- **How it is read:** `packages/gates/src/gitleaks_rules.ts` parses the file with the kernel's one TOML parser and rewrites each Go (RE2) pattern as a JavaScript one with the same meaning (`goRegexToJs`: Go's inline `(?i)`, `(?-i:…)` and `(?s:…)` with no RegExp modifier group — a leading `(?i)` becomes the `i` flag, any other is expanded to `[xX]` letters and case-closed classes, `.` under `s` to `[\s\S]` — so the rules run on Node 22's V8 12.4, which has no modifiers; `(?P<name>`, `\z`, POSIX classes, a `]` first in a class, Go's `\s`). All 222 rules of v8.30.1 run on every supported Node (22.13 and later; `gitleaks_rules.spec.ts` compiles every rewritten pattern under `node --no-js-regexp-modifiers`). A rule whose pattern cannot be rewritten exactly (`\Q…\E`, `\p{…}`, `\x{…}`, `\C`, the `U` and `m` flags) or that JavaScript still cannot compile is not run and is named with its reason (`gitleaksRuleSet().notRun`; the history scan's reason says how many and which), never skipped silently. The scan (`secrets.ts`) follows gitleaks: whole fragments, keywords, the secret group, entropy, the global and per-rule allowlists, `gitleaks:allow`, and a generic finding dropped where a specific rule found the same secret. Remaining differences: JavaScript's `\S` and `.` treat `\v`, `\r` and Unicode separators differently from Go, and case-insensitive matching does not fold non-ASCII letters.
- **Rebuild:** download `config/gitleaks.toml` and `LICENSE` of a newer release with the owner's approval (DEC-08), run `node packages/gates/data/gitleaks/vendor.mjs <gitleaks.toml> <LICENSE> <vX.Y.Z> <YYYY-MM-DD>` (it copies both byte for byte, prints the hashes and rule count, and names any rule JavaScript cannot run once `packages/gates` is built), then record the version, date, hashes and count here and in NOTICE. `gitleaks_vendored.spec.ts` checks the file against this README; `gitleaks_rules.spec.ts` checks that every rule runs under gitleaks' own id.
