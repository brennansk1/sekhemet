# Sekhemet — Complete Feature Inventory & Implementation Status Audit

> **Sources audited:** `Board-Native Local-First AI Coding Harness — Design v2.md` (2,805 lines; byte-identical to v1), `DEFINITION_OF_DONE.md`, `AGENTS.md`, `CHRONICLE_GATE_PROJECT_SPEC.md`, `SHOWCASE_TRIFECTA_SPEC.md`
> **Code audited:** every file under `packages/*/src` and `apps/harness/src` (≈3,600 LOC total)
> **Date:** 2026-09-17

## Status legend

| Tag | Meaning |
| --- | --- |
| **MISSING** | No code exists anywhere in the monorepo. |
| **SHALLOW** | Code exists but is a stub/simplification that does not do what the doc describes. |
| **DEAD** | Implemented but never imported or invoked by any production caller (only tests, or nothing). |
| **BUILT** | Genuinely implements the spec as written. |

## Executive summary of the audit

The design specifies roughly **310 distinct buildable units**. Current state:

| Status | Count (approx) | Share |
| --- | --- | --- |
| MISSING | ~225 | ~72% |
| SHALLOW | ~45 | ~15% |
| DEAD | ~25 | ~8% |
| BUILT | ~15 | ~5% |

**The five structural findings that dominate everything else:**

1. **`@sekhemet/context` is entirely DEAD.** Zero production imports. `grep -rn '@sekhemet/context' packages apps --include='*.ts'` returns only the package's own test files. The executor never builds a context pack, never sees the repo map, never loads a skill, never applies a playbook rule, never masks an observation, and never receives a `GateFailure`.
2. **The executor prompt is a hardcoded string.** `packages/loop/src/session.ts:343` sends the model literally `"Executing card ${this.cardId} turn ${turnIndex}. Proceed with edits."` — no system prompt, no card spec, no acceptance criteria, no scope, no repo map, no tool schemas, no prior turns, no gate failure. The 4-zone prompt architecture, prefix-cache byte-stability, and the entire small-model-leverage thesis are unexercised.
3. **The sandbox does not sandbox.** `generateSeatbeltProfile()` (`packages/sandbox/src/seatbelt.ts`) is never called by `ProcessSandbox.execute()`, which does a bare `spawn()` with inherited `process.env` and no `sandbox-exec`/Landlock/seccomp wrapper. `SandboxOptions.allowedPaths` and `allowNetwork` are accepted and then discarded. Network egress is not blocked. Restricted mode is a CLI boolean that changes nothing.
4. **There is no loop.** `sekhemet run` (`apps/harness/src/index.ts:409`) calls `session.executeTurn()` exactly once and exits. No turn loop, no retry ladder, no rung transitions, no checkpoint commits, no card-state transitions, no evidence bundle.
5. **`gates.toml` is never read.** No parser, no hash verification, no `[[gate]]` table, no layers, no timeouts, no per-gate parsers. `DeterministicGateRunner.runGates()` hardcodes `pnpm typecheck` / `pnpm test` / `pnpm lint` and short-circuits on first failure.

**In-flight uncommitted work (concurrent agent):** `packages/loop/src/{tools,symbols,observation,paths,text,glob}.ts` are untracked and actively being written. They are a substantially better tool catalog (real path confinement with symlink resolution, CRLF-aware edits, uniqueness enforcement, `ask`-tier approval escalation, head/tail observation clamping). They are **not exported from `packages/loop/src/index.ts` and not imported by `session.ts`** — currently DEAD. They are marked separately below.

# Features most likely to be overlooked

These are specified **once, deep in prose**, carry an exact algorithm, threshold, filename, or protocol detail, and are easy to miss when skimming the doc. Every one is currently MISSING or SHALLOW.

1. **Binary search for repo-map budget fit** (§400) — the map builder must *binary search* over the top-ranked symbol set to land exactly at the token budget, not greedily truncate.
2. **Aider's edge-weight multipliers** (§400) — mentioned identifiers weighted up, well-named identifiers weighted up, in-scope files weighted highest. Personalized PageRank is **seeded toward `filesTouched`**, not uniform.
3. **Repo-map cache key = path + mtime + content hash** (§400) — all three, not just mtime.
4. **Graduated masking pressure at 70 / 80 / 85 / 90%, hard `budget_exhausted` at 95%** (§465) — four escalation tiers, not one.
5. **Goal re-injection at the *tail* of every step** (§420, §466) — explicitly to counter "lost in the middle"; placement is the mechanism.
6. **"Reasoning traces stripped between steps unless the model registry explicitly notes a benefit"** (§469, §643) — a per-model registry flag (`reasoning.stripTraces`), not a global setting.
7. **Observation pointer must carry an `EvidenceRef`** (§420) — `[Observation #4: tsc completed with 0 errors. 1,420 tokens masked. EvidenceRef: ev_8f9a2]`. Without a retrievable ref the masking is lossy, not deferred.
8. **RTK's four named strategies** (§424-428) — Smart Filtering, **Grouping** (test suites by status, lint warnings by rule), Truncation, **Deduplication** (repeated lines → frequency counts). Two of the four are usually forgotten.
9. **Condensing must be "strictly lossless regarding repair data"** (§430) — error lines, file paths, test names, exit codes are protected; head/tail elision violates this by construction.
10. **Stall signature includes `repoStateHash`** (§616) — "Two identical signatures **with unchanged repo state**". Without the repo hash, a legitimate retry after an intervening successful edit is misclassified as a stall.
11. **Rung attempt caps: 2 / 1 / 1** (§634-637) — Rung 1 allows two attempts, Rungs 2 and 3 exactly one each.
12. **"At most three failures per repair attempt, chosen by topological dependency order"** (§1222, §560) — the ordering rule is the point: fixing the first often clears the rest.
13. **`minimalRepro` field on `GateFailure`** (§1218) — the exact command to reproduce, not a description.
14. **Difficulty routing thresholds < 4 / 4–7 / > 7** (§733) — and specifically that 4–7 triggers an **edit sketch** rather than direct execution.
15. **INVEST-S: context pack ≤ 25% of tier working context AND step budget ≤ 40** (§712) — two conjunct numeric conditions.
16. **INVEST-E: difficulty > 7 forces re-split** (§711) — a hard gate, not a warning.
17. **"If a spec triggers more than 3 questions, the planner rejects the spec as under-specified"** (§760).
18. **Ask-vs-assume 15% override threshold per category** (§831, §2716) — "if human override rate on assumptions in category C exceeds 15%, category C shifts from assume to ask."
19. **`DecisionRequest.policy` = `safe_default` | `default_deny`** (§780, §793-795) — and the rule that destructive actions are **never** auto-approved at deadline.
20. **`decision/default_applied` event type** (§794) — distinct from `decision/answered` (§752).
21. **Scope drift > 20% halts *auxiliary card creation*** (§906) — the response is a creation freeze plus a decision request, not just a warning.
22. **Column p95 > 2.5 × p50 cycle time** (§907) — note the doc's own internal conflict with the mermaid diagram's `2x` at §898.
23. **Blocked-time thresholds: 12 h idle, 2 h during active work** (§908) — two different thresholds by context.
24. **Failure-concentration Pareto: ≥ 3 gate failures in one source file → re-split along Interface or Data boundaries** (§909) — the remedy names specific SPIDR slices.
25. **RAID risk register: high-risk assumption aged > 24 h → dispatch a time-boxed verification spike** (§911).
26. **`ReviewWIP` floored at 1 and rounded down, computed from the project's own accepted-card history** (§728-729) — not a config constant.
27. **Back-pressure blocks entry to *Verify*, not to Review** (§392, §910) — the block is one column upstream of where it is naturally implemented.
28. **Parent rollup requires the parent's own integration gate on the merged result** (§380) — "Rollup never infers success from children alone."
29. **Regression protection: a revision that regresses a previously passing gate returns to *Planning* with the regression named** (§384) — not to In Progress.
30. **Checkpoint on every gate-passing step *and* every masked observation boundary** (§1490) — the second trigger is easy to miss.
31. **`refs/sekhemet/checkpoints/<card-id>`** (§1541) — the exact raw-checkpoint ref namespace used by the Gemini Relay-Finisher protocol (AGENTS.md §2).
32. **Branch naming `sekhemet/<project>/<card-id>-<slug>`, created from the *parent card's* branch when one exists** (§1514).
33. **Accepting a lower card in a stack rebases the cards above it and re-runs their gates** (§1553).
34. **Conflict hunks are delivered as typed failures; conflicts outside declared scope park the card** (§1545).
35. **Vision model can fail a card but can never pass one; new or changed baselines always require human approval** (§957) — an asymmetric authority rule.
36. **axe-core at exactly 1280px and 375px viewports, zero critical violations** (§954).
37. **`maxDiffPixelRatio: 0.01` with dynamic content masked and animations disabled** (§953).
38. **Layout-bounds predicates: overlap, `width<=0 || height<=0`, `x<0 || y<0`, `scrollWidth > clientWidth`** (§952) — four specific programmatic assertions.
39. **Mutation testing is diff-scoped only and never gated at 100% because equivalent mutants exist** (§961); advisory before blocking.
