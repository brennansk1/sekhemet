## onboard.ts: does it serve the "harness for professional teams" positioning?

**What it gets right.** It follows the seven steps in the design (`HARNESS_DESIGN.md:2343-2351`) in order. Everything it writes is a draft under `.sekhemet/onboard/`, and nothing is enforced without `--apply` (`:505-519`). The spec asserts that `AGENTS.md` is untouched without `--apply` (`onboard.spec.ts:131`). Rules enter the learning store as *candidates* (`:445-454`), and convention drift is posted to the PM thread (`:609-628`). The shape matches what a professional team would expect.

**Where it fails a team repository:**

1. **The team's real gates are ignored.** `detectCommands` reads CI workflows (`:167-188`), but its output feeds only the AGENTS.md draft. The proposed `gates.toml` comes from `gateTemplate` or `deriveGates` (`:413-415`), which make no use of CI. It prefers `templates.ts`, the deriver that domain 1 found has no typecheck and no `protected` list, and whose Python template gates on ruff and mypy even when the repository uses neither. This is effectively a **fourth** gate-derivation path, besides `init`, `gates init` and bare `sekhemet`. For a team, the CI pipeline *is* the definition of done, and onboarding throws it away.
2. **Multi-line CI steps are missed (confirmed).** The regex `^\s*(?:-\s*)?run:\s*(.+)$` (`:172`) captures `|` for a `run: |` block. Most real workflows use that form, so detection returns nothing. The keyword classifier (`/\btest\b/`) would also match `echo test`. `${{ matrix }}` placeholders pass through unresolved.
3. **`--apply` overwrites a hand-tuned `.sekhemet/gates.toml` with no `--force` and no backup (confirmed).** See `:506-508`. `init` and `gates init` both refuse to do this (`index.ts:865-869`).
4. **`AGENTS.md` is not idempotent (confirmed).** Every `--apply` appends another `<!-- sekhemet onboard -->` block (`:470`); the marker count went 0 → 1 → 2 → 3 over three runs. The draft also writes Sekhemet's own house rules into the team's file (`:326-329`: "at most 3 files and 200 changed lines", test-first). Those are Sekhemet's bounds, not the team's conventions.
5. **Convention drift fires on every run (confirmed).** The snapshot is stored as `loadProjectConventions()` output, which carries a `From AGENTS.md:` prefix (`context/src/conventions.ts:60`). The check compares it with `extractConventions()` output, which has no prefix (`:593-599`). Any repository whose AGENTS.md has convention bullets therefore reports "documented conventions changed" after any commit, and `overnight` posts that to Seshat's thread every night (`overnight.ts:96`). The spec misses it because it asserts with `toContain` (`onboard.spec.ts:157`). This is drift from the design, which says drift is compared "against the playbook" (`HARNESS_DESIGN.md:2374`); the code compares against a snapshot file.
6. **Conventions are thin.** The detection covers file-name case, test layout, five test frameworks and `throw new XError` (`:194-270`). It misses what a team repository actually encodes: formatter and linter configs, commit conventions, CODEOWNERS, PR templates, pre-commit hooks, workspace packages, and the `packageManager` field (which `deriveGates` reads). `pyproject.toml` always adds `pytest -q` (`:143`). A malformed `package.json` aborts the whole run (`:129`).
7. **Unconfined execution on a repository not yet trusted.** Step 2 starts `rust-analyzer`, `pyright` and `typescript-language-server` on the repository before any trust decision (`:388-406`). rust-analyzer runs `build.rs` and proc-macros by default. This belongs with S3a (one confined execution path) and S9 (workspace trust).
8. **Not discoverable.** No first-run path, dashboard view or PM tool mentions `onboard`. A team finds it only by reading the source. It should *be* the first run for an existing repository (P10).

**Tests (DoD §2):** They use real git and real temporary directories, which is good. The negative cases required by DoD §2B are missing: re-apply idempotency, an existing gates.toml, malformed manifests, multi-line CI, and a quiet repository that should report no drift. The drift assertion is too weak to catch the false positive.

**Complexity:** `runOnboard` is 170 lines in one function, and three command detectors duplicate each other (`detectCommands`, `deriveGates`, `templates.ts`). **Verdict: refactor.** It should become the professional first run. Keep the seven steps. Make CI and the project's scripts the single source for the gate proposal (merged with P10 and the one-deriver change from domain 1). Diff against the existing `gates.toml` instead of overwriting it, write idempotent marked sections, fix the drift comparison, and confine step 2.

## Other notes

- **mutation_step.ts.** It never runs the tests on the *unmutated* checkout (`:103-132`; `eval/src/mutation.ts:97`). A checkout whose tests cannot run at all (no dependencies installed, wrong toolchain) therefore reports every mutant as killed: score 1.0 and no proposals. A card with no mutable lines also records `score: 1` (`:145`) instead of "not applicable". The spec passes only because its fixture uses `node:test` with no dependencies. Python and Rust changes are skipped silently (`:39`). The fix is a baseline run that must pass before any mutant counts, `score: null` when `total` is 0, and a negative test for each.
- **instrumentation.ts.** `InstrumentedAdapter` forwards only `generate` (`:22-60`). `session.ts:920` reads `contextWindow`, `:971` reads `nativeTools`, and `:1211` reads `preferredToolArm`, so every `m0` benchmark attempt runs a different prompt shape and budget than production. It also does not meter `cachedPromptTokens`, which M8 needs. This should join M4 (provenance) in Tier 1.
- **diagnostics.ts.** `playbookDoctorCheck` calls `playbookDiagnostics({ repoPath })` with no inputs (`wave2.ts:1111`). Only the rule-bloat line can ever fire. The check also reads `playbook.toml` rules only, apparently not the rules learned on the ledger, which is where onboarding puts its rules. Net gain is a raw difference with no significance test; that belongs with Tier 3's "paired trials with statistics".
- **constants.ts.** `DEFAULT_TIER_BUDGET.workingContextTokens = 32_768` (`:60`), and no production caller passes `tierBudget` (no match for `tierBudget` under `apps/*/src`). Meanwhile the managed Worker runs at 16,384 on hosts under 32 GB (`llama_server.ts:531,558`). INVEST's "a quarter of the window" is really half. The design references are stale: `§754-760` is a blank line, and `§2485` is a row about LSP. The 3-file / 200-line bound is repeated in `constants.ts:30`, `gates/config.ts:81`, `templates.ts:136`, `fixture_repo.ts:33` and `onboard.ts:327`.
- **calibration_store.ts.** Nothing stops the same assumption being recorded twice. With `minimumSamples` 1 (`calibration.ts:39`), one override (1/1 > 15%) flips a category to "ask". Payloads are cast without validation (`:25`); the Zod proposal would cover this.
- **working_memory.ts.** An error that disappears because the failure changed shape (for example a test file that stops compiling) is reported as "fixed: … (do not reintroduce)" (`:43-50`). Only the first `:line:col` is stripped (`:39`). Three tests, all happy-path.
- **ts_service.ts.** `startsWith(this.root)` also accepts sibling paths that share the prefix (`:88,143`), and the file list is re-walked on every query (`:39`). The tests are good (`tools_wave2.spec.ts:58`). If M2 drops `tool_search`, keep these tools in the Worker's fixed set.
- **mock_adapter.ts and fixture_repo.ts.** These are test infrastructure exported from the product packages (`models/src/index.ts:3`). Move them to a `/testing` subpath export. Make `exhaustion: "throw"` the default so under-scripted tests fail instead of looping.

## Proposals (owner's decision)

- **Proposed cut:** none. Every file is reachable or is legitimate test support.
- **Fold onboarding into P10 "One first run".** For an existing repository, the first run *is* onboarding: CI plus scripts give one gate proposal, which is shown as a diff and accepted once.
- **Library:** a YAML parser such as `yaml` (ISC; licence to verify) for workflows, instead of the regex at `onboard.ts:172`. Optionally, reuse an existing CI-to-command extractor. The design already names `crag` and `codebase-md` (`HARNESS_DESIGN.md:2376`); their licences and maintenance are unverified.
- **Tier 1 additions:** a transparent `InstrumentedAdapter` (next to M4) and a mutation baseline run (next to M6).
